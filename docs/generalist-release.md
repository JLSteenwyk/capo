# Generalist release evidence

This checklist maps the generalist reliability requirements to implementation and verification. It separates host guarantees, model observations, and deployment checks. The tested runtime is `7945543`; documentation-only updates followed. The full local suite passed 509 tests, and the GitHub Python matrix passed on that revision and `a19f8c0`.

| Requirement | Implementation and evidence | Practical limit |
| --- | --- | --- |
| One ordinary conversation loop with enabled capabilities | `slack.py` routes new ordinary requests to `CapabilityConversation`; `test_shared_conversation.py` exercises calendar/email composition without the old classifier. `capabilities.py` constructs the enabled catalog. | Saved legacy classifier attempts retain their original path for compatibility. |
| Shared specialist expertise; bounded development and browser handoffs | `specialist_tools.py` and `workflow_tools.py`; workflow tests check trusted repositories, original owner requests, thread scope, and durable handoff receipts. | A queued handoff is not a completed objective. Publication and browser approvals remain separate. |
| Owner authorization, commands, no-mention replies, activity, cancellation, receipts | `test_slack.py` covers owner/workspace/channel restrictions, known threads, direct commands, activity failures, durable chunk delivery, and approval binding. `test_request_control.py` checks cancellation before and during writes. | Automated Slack-client tests do not constitute a new live conversation for each behavior. |
| Calendar find, inspect, select, act, verify | `calendar_tools.py`, `calendar_actions.py`, and `calendar.py`; tests cover metadata, resource identity, restrictions, preserved fields, all-day/timezone behavior, verification, and reconciliation. Model comparisons check colliding event IDs, reminders, and stale revisions. | Primary reads pass live. Metadata discovery requires an additional Google read grant; live discovery verification is pending. Shared/guest/recurring event write restrictions remain in place. |
| Gmail correspondence, pagination, attachments, drafts | `gmail.py` and `drafts.py`; coverage tests retain successful reads when later reads fail, expose unread IDs/truncation, and qualify authorship. Draft tests check MIME contents, recipients, thread identity, readback, uncertain saves, and deletion reconciliation. | Attachments support bounded text formats, not arbitrary document interpretation. Sent labels alone do not establish authorship. No send tool is exposed. |
| GitHub current authoritative state | `github_tools.py` provides bounded, configured-repository inspection. Tests cover endpoint restrictions, discovered IDs, pagination, logs, and errors. The model notification case checks current PR head/checks against an old failure email. | Read coverage is bounded and disclosed; coding/publication reuse existing gateways. |
| Research missing facts before clarification | The shared prompt and tool receipts distinguish available facts, assumptions, uncertainty, and access failures. Model cases cover official-source lookup, two equally eligible dates, empty searches, and partial pages. | Useful clarification and factual attribution still require semantic evaluation. Meeting-brief source attribution failed one targeted regression and is documented. |
| Current time and source-relative dates | Each new reasoning step receives local time. `dates.describe` and calendar `local_dates` calculate weekdays. | Original objective, corrections, retries, restarts | `request_memory.py`, `request_updates.py`, and checkpoint handling retain original context and receipts. Shared-conversation tests exercise accepted same-owner/thread corrections and reject other threads/users. Model correction tests stop a superseded write before execution. | An already-sent change cannot be retroactively prevented; its receipt is retained. Synthetic model interruption is separate from live Slack delivery. |
| Bounded execution and multi-part accounting | `execution_limits.py` pins validated budgets; `request_outcomes.py` validates declared outcomes and receipt references. Tests cover exhausted budgets, oversized evidence, malformed completion repair, and restart reuse without duplicate actions. | Outcome inventories are model-declared; host checks cannot prove every semantic requirement or factual statement. Unassessed legacy completion is labeled. |
| Verify writes and reconcile uncertainty | Calendar and draft adapters use authoritative readback and durable effects. Tests distinguish unsent preflight rejection from an outbound uncertain write. Model runs exercise stale resources and lost responses without duplicate writes. | Unknown outbound results remain pending until reconciliation. |
| Retrieved content cannot grant authority; monitoring remains read-only | Host permissions and tool schemas constrain actions. Reviews were by the implementation agent, not independent graders; no statistical improvement rate is claimed. |
