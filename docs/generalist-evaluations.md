# Generalist outcome evaluations

The evaluation package separates simulated service state from the real Capo reasoning loop and adapters. `capo.evaluations.runner.run_case(provider, name, output, mode)` accepts an injected provider and writes private artifacts outside the repository. Use a fresh directory for each case. `mode` labels scripted host tests versus model-driven runs; it is not evidence of which model or subscription was used. Model runs must use the configured subscription provider, with provider provenance recorded separately.

The scenarios cover moving a personal appointment, selecting a work calendar with a colliding event ID, respecting the guest-event edit restriction, combining a calendar agenda with email for a meeting brief, and drafting a contextual reply. Calendar selection and reply drafting are marked held out from model evaluation and prompt tuning; scripted tests may validate their fixture plumbing. The runner exposes only calendar/date/clock tools and, for mail scenarios, Gmail tools backed by synthetic data. It does not connect to Google, send Slack messages, or expose web and other service fallbacks. The synthetic Gmail service supports bounded fixture correspondence and in-memory drafts; it has no send endpoint. Search behavior is simplified to the fixture mailbox, not a complete implementation of Gmail search. Fake Google PATCH behavior preserves untouched fields and removes explicitly cleared fields.

Grades compare the resulting calendar state and write count with the requested outcome, including preserved descriptions and untouched calendars. Mail checks require inspected source bodies, the exact recipient with no extra Cc/Bcc, preserved subject/reply headers/thread identity, and expected fact tokens. Fact-token checks are incomplete semantic checks; they cannot establish writing quality or rule out all invented claims. A confident answer without the requested update fails. Where answer interpretation has not been assessed, the result stays unknown rather than assuming success or failure. Unnecessary clarification and unsupported-claim metrics currently remain null pending separate review.

Each run stores a summary, before/after service state, and the normal private request artifacts. The summary includes revision, implementation hash, fixture hash, harness hash, mode, elapsed time, tool attempts, writes, and checks. This runner covers shared reasoning and calendar/Gmail adapters, not end-to-end Slack routing or other integrations. It is the first part of the broader evaluation harness, not a completed benchmark.

Run deterministic harness checks with `PYTHONPATH=tests python3 -m unittest test_generalist_evaluations -q`. These inject scripted decisions and establish fixture and grading behavior; they do not measure model capability. No baseline-versus-candidate model comparison has been run for this generalist change yet. The preserved baseline must remain unchanged until both revisions are evaluated with equivalent fixtures and conditions. GitHub, further research combinations, recovery scenarios, comparison reporting, and bounded subscription runs remain to be added.
