## Perform the completion audit

1. Inspect the actual worktree, committed source, CLI help, private runtime state, live process handles, and remote PR state. Do not infer current success from a previous report.
2. Run `python3 -m unittest discover -s tests -q` and `git diff --check`. Confirm tests cover the promised behavior, especially negative paths. Fake-provider tests remain labeled as automated evidence.
3. Exercise an integrated objective in a trusted repository with meaningful acceptance checks and both worker providers. Inspect the final diff and delivery evidence rather than relying on a terminal model message.
4. Verify Slack using the real configured app. Preserve owner-only policy. Record whether clarification, status, cancellation, and exact-candidate approval were actually exercised.
5. Inspect the resulting draft PR and synchronized CI status. Confirm its commit matches the accepted candidate and publication retries cannot create duplicates.
6. Inspect the self-improvement baseline and candidate evidence, plus changes to governance-sensitive code. Confirm the active supervisor was not silently replaced.
7. Reconcile documentation and publish verified milestones. Report any missing credentials or other external blockers precisely after completing all independently testable work.

A missing live Slack setup, missing live draft PR, or unverified integrated VM run must remain explicit. Do not relabel the release complete by dropping one of those requirements. No PR merge, paid API fallback, unrelated external message, unrestricted computer-use capability, or autonomous promotion is required for this release.
